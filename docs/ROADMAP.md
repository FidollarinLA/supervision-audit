# 可持续迭代路线

按验收价值推进，不按代码行数或 token 用量推进。每个增量都应有明确输入、输出、验证和边界。

## 当前已交付

- MoonBit 审计核心：标签、角色/纯文本策略、Padding、来源、拼接边界和资源预算。
- JSONL 样本标准化及证据保留；JSON 文档接口；离线 CLI。
- 预训练与微调合成场景；修复对比、逐 token 查看、样本总览、完整报告导出。
- 有界界面呈现；编辑后使旧报告失效；大诊断集合的索引比较。
- 自动检查、跨后端测试、独立判定器、复现指南和开源来源说明。

## 优先级一：真实训练流程适配

- [ ] 增加一个固定版本 tokenizer / collator 导出工具，提供来源明确且可重建的微型公开输入。
- [ ] 验证模型内部 label shift 的约定，用参考实现核对损失掩码；无需下载大型模型或付费 API。
- [ ] 分开记录预训练跨文档策略和微调 assistant-only 策略，保留不能证明的注意力隔离问题。
- [ ] 把参考输出与 MoonBit 审计结果的对应关系写成文档与自动测试。

## 优先级二：发布与外部复现

- [ ] 查询实际 Mooncakes 账号和模块名，核对发布文件及许可证。
- [ ] 发布版本并从一个干净的外部 MoonBit 模块安装、运行最小样例；无凭证时报告具体缺项。
- [ ] 根据用户本人最终申报书核对每项承诺，避免未完成能力被写成已交付。
- [ ] 完成桌面和窄屏浏览器的真实视觉检查，保存真实截图；不能以模拟 DOM 测试代替视觉检查。

## 优先级三：规模与使用体验

- [ ] 将大文件检查移到后台 worker，补取消操作及消息返回一致性测试。
- [ ] 研究流式 JSONL 审计，明确跨批次 ID 唯一性和资源预算。
- [ ] 增加可解释的命令行摘要与报告版本字段，保证输出兼容。
- [ ] 获取真实外部试用反馈，逐条记录并修复；不编造试用人数或评语。

定时迭代先读取本路线和 WORKLOG。避免多个运行同时编辑，不改变申报名称和仓库归属；不上传私有数据，不制造重复项目。每轮保留可核查的实际验证结果。
